# Билет пускалки, схема 1

Менеджер выдаёт полный билет одной попытки и предоставляет связанный `.unl`.
Пускалка не обращается к БД Moodle или UNetLab и не запрашивает описание лабы
по сети. Путь в билете — путь **внутри контейнера**, а не путь на бате.

```json
{
  "schema": 1,
  "ticket_id": "ticket-20261012-001",
  "attempt_id": "attempt-001",
  "issued_at": "2026-10-12T00:00:00Z",
  "user": {
    "id": 42,
    "username": "student42"
  },
  "lab": {
    "id": "70bcb98d-5655-4e87-a1b3-266e9287d42d",
    "version": "1",
    "unl": "/ticket/lab.unl"
  },
  "storage": {
    "templates": "/templates",
    "progress": "/progress"
  },
  "consoles": {
    "bind": "0.0.0.0",
    "vnc_base_port": 5900,
    "serial_base_port": 4000
  },
  "node_overrides": {
    "1": {
      "image": "linux-v1",
      "cpu": 1,
      "ram_mb": 512,
      "ethernet": 2
    }
  },
  "external_networks": {}
}
```

В примере профиль `.unl` определяет оставшиеся параметры ноды. Образ
`linux-v1` должен находиться в `/templates/linux-v1` и содержать диски,
подходящие для этого профиля. Пример билета не поставляет гостевой образ.

## Поля

| Поле | Смысл |
| --- | --- |
| `schema` | Версия JSON-контракта; первая итерация использует `1` |
| `ticket_id` | Идентификатор билета менеджера |
| `attempt_id` | Единица изоляции и размещения; одна попытка — одна пускалка |
| `issued_at` | Время выдачи в ISO 8601, UTC |
| `user.id`, `user.username` | Идентификатор и логин пользователя Moodle для связи с попыткой |
| `lab.id` | UUID лаборатории из `.unl` |
| `lab.version` | Зафиксированная менеджером версия определения лаборатории |
| `lab.unl` | Абсолютный путь к переданному `.unl` |
| `storage.templates` | Абсолютный путь к каталогу неизменяемых шаблонов; mount read-only |
| `storage.progress` | Абсолютный путь к предоставленному каталогу этой попытки; mount read-write |
| `consoles.bind` | Адрес внутри контейнера для VNC/Telnet; доступ ограничивает сеть бати |
| `consoles.vnc_base_port` | Начало диапазона VNC-портов |
| `consoles.serial_base_port` | Начало диапазона последовательных Telnet-консолей |
| `node_overrides` | Необязательные переопределения нод из `.unl`, ключ — ID ноды строкой |
| `external_networks` | Необязательное отображение `pnet*` на подготовленные Linux bridges контейнера |

Точное подключение к консоли менеджер получает из `GET /consoles`, а не
вычисляет самостоятельно. Логин не является механизмом авторизации пускалки.
Она исполняет билет доверенного менеджера; права учащегося проверяются выше.
Поле `bind` в ответе описывает адрес слушателя; при `0.0.0.0` менеджер
подставляет фактический адрес контейнера в управляющей сети бати.

## Переопределение ноды

Поддерживаемые поля: `image`, `cpu`, `ram_mb`, `ethernet`, `arch`, `nic`,
`qemu_args`, `qemu_binary`, `console`, `uuid`, `firstmac`, `delay`,
`nic_overrides`. Неизвестные поля отклоняются, чтобы ошибка в ресурсе не
привела к запуску с другим значением. `image` задаёт имя неизменяемого каталога шаблона относительно
`storage.templates`; `arch` выбирает поддерживаемую архитектуру QEMU,
`nic` — модель виртуального сетевого адаптера. В этой итерации контейнер
содержит QEMU для `x86_64` и `i386`.

`qemu_args` — список отдельных аргументов, а не shell-команда. Такие параметры
составляет менеджер или профиль; ввод аргументов от учащегося не предусмотрен.
Пускалка сохраняет собственное управление дисками, TAP, QMP и консолями.

Билет не хранит отдельный счётчик нод: состав определяется `.unl`, поэтому
количество нод и связность не могут расходиться с дублирующим полем. CPU и RAM
берутся из определения лаборатории и переопределений. Батя выделяет ресурсы
на всю лабораторию с накладными расходами; контейнер не резервирует их сам.

## Внешние сегменты

```json
{
  "external_networks": {
    "pnet0": "uplink0"
  }
}
```

Такой билет предполагает, что менеджер уже подготовил в контейнере Linux
bridge `uplink0` с MTU не ниже 9000 и подключил к нему нужный внешний uplink.
Внутренние bridge-сегменты `.unl` не требуют внешних интерфейсов.
Управляющая Docker-сеть не становится частью лабы автоматически.

## Повторный запуск

Менеджер сохраняет связь попытки с точной версией `.unl`, профилей и шаблонов.
Для восстановления он передаёт новому контейнеру то же описание и постоянный
каталог, сохраняя пути шаблонов внутри контейнера. Наличие дисков означает
повторное использование прогресса, а не создание новой попытки.

`ticket_id` и время выдачи помогают менеджеру учитывать запросы; они сами
не являются распределённым lock или защитой от двух активных пускалок.
Единственный владелец попытки гарантируется слоем размещения до запуска.
Правила срока действия, подписи, автопроверки и KEMU агента относятся
к следующим этапам и здесь не добавляются.
